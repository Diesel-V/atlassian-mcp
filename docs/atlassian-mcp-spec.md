# Change: atlassian-mcp — доступ LLM к Confluence и Jira под правами пользователя

> Формат: OpenSpec (proposal → specs → design → tasks)
> Статус: реализовано (v0.2.0), до развёртывания и согласования с ИБ
> Владелец: см. CODEOWNERS / внутреннюю копию
> Дата: 2026-11-02

---

## 1. Proposal

### Why

Типовая интеграция Open WebUI с Confluence — инструмент сообщества, который ходит в Confluence под одной общей служебной учёткой:

- Служебная учётка видит больше, чем обычный сотрудник, включая закрытые пространства. Через бота любой пользователь может прочитать то, к чему у него нет доступа в Confluence. Это обход разграничения прав.
- Ограничение пространств задано в пользовательских настройках, и пользователь может снять его сам.
- Запрос подставляется в CQL без экранирования (CQL-инъекция).
- Инструмент блокирует event loop Open WebUI на время поиска: поиск одного пользователя подвешивает сервис для всех.
- Поиск разбивает запрос на слова через OR и не умеет искать по автору. Поиск по ФИО фактически не работает.
- «Отдельные» ассистенты по отделам ходят под той же учёткой, разделение доступа фиктивное.
- Пароль служебной учётки хранится открытым текстом в БД Open WebUI.
- Агентам (OpenCode, прод-агенты) нужен такой же доступ к Confluence и Jira, но безопасного способа его дать нет.

### What Changes

- Собственный MCP-сервер `atlassian-mcp` для Confluence и Jira Data Center.
- Доступ к данным только под правами конкретного субъекта: человека (OAuth 2.0 через Confluence/Jira) или агента (выделенная служебная учётка с минимальными правами).
- Одна модель в Open WebUI — «Atlassian» на self-hosted LLM. Отдельные ассистенты по отделам не нужны.
- Подключение агентов: персональные ключи (агент от имени человека) и Keycloak client credentials (автономные агенты).
- Аудит всех вызовов.
- **BREAKING:** удаляются прежние инструменты и модели Confluence в Open WebUI, общая служебная учётка выводится из использования.

### Impact

- Пользователи Open WebUI: один раз нажимают «Разрешить доступ» к Confluence и Jira (вход через SSO, пароль не нужен).
- Разработчики с OpenCode: выпускают себе ключ MCP на странице «Мои доступы».
- Админы Confluence/Jira: регистрируют входящие OAuth 2.0-приложения (один раз).
- Девопсы: DNS и TLS для MCP-сервера, развёртывание.
- ИБ: согласование схемы до перевода на прод.

## 2. Specs

### Capability: identity — определение субъекта запроса

#### Requirement: Идентификация пользователя Open WebUI

Сервер SHALL определять пользователя по SSO-токену Keycloak, который Open WebUI передаёт с каждым вызовом, и SHALL проверять подпись, `iss`, `azp` и срок действия токена.

##### Scenario: Валидный токен
- **WHEN** Open WebUI вызывает инструмент с Keycloak-токеном `iss` = доверенный realm, `azp=open-webui`, срок не истёк
- **THEN** сервер определяет пользователя по `preferred_username`
- **AND** выполняет запрос под его Atlassian-токеном

##### Scenario: Невалидный или просроченный токен
- **WHEN** подпись не сходится, токен просрочен или `azp` не из списка разрешённых
- **THEN** сервер отвечает 401 и не обращается к Confluence/Jira

#### Requirement: Персональный ключ агента

Сервер SHALL выдавать пользователю персональные ключи для агентов. Агент с ключом действует строго с правами этого пользователя.

##### Scenario: Выпуск ключа
- **WHEN** пользователь на странице «Мои доступы» (вход через SSO) создаёт ключ с названием и сроком
- **THEN** ключ показывается один раз
- **AND** в БД хранится только его хеш

##### Scenario: Вызов агентом
- **WHEN** агент вызывает инструмент с действующим ключом
- **THEN** запрос выполняется под Atlassian-токеном владельца ключа
- **AND** в аудите фиксируются владелец и название ключа

##### Scenario: Отзыв
- **WHEN** пользователь отзывает ключ или ключ истёк
- **THEN** следующий вызов с ним получает 401

#### Requirement: Автономный агент

Сервер SHALL принимать Keycloak-токены client credentials от зарегистрированных клиентов и сопоставлять каждого клиента с его выделенной служебной учёткой Atlassian.

##### Scenario: Зарегистрированный агент
- **WHEN** агент приходит с client credentials токеном клиента из реестра агентов
- **THEN** запрос выполняется под служебной учёткой этого агента

##### Scenario: Незарегистрированный клиент
- **WHEN** токен валиден, но клиента нет в реестре агентов или агент выключен
- **THEN** сервер отвечает 403 и не обращается к Confluence/Jira

#### Requirement: Нет общей учётки

Сервер SHALL NOT выполнять запросы под учёткой, не принадлежащей субъекту запроса. Резервной учётки «по умолчанию» нет.

##### Scenario: Пользователь не дал доступ
- **WHEN** пользователь Open WebUI вызывает поиск, но не подключил Confluence
- **THEN** сервер не обращается к Confluence
- **AND** возвращает ссылку «Разрешить доступ к Confluence»

### Capability: atlassian-auth — OAuth 2.0 с Confluence и Jira

#### Requirement: Подключение доступа

Сервер SHALL получать токены пользователя через OAuth 2.0 Authorization Code (+ PKCE) у Confluence и Jira Data Center (входящие ссылки на приложения).

##### Scenario: Первое подключение
- **WHEN** пользователь переходит по ссылке «Разрешить доступ»
- **THEN** Confluence/Jira проводит вход через SSO и показывает экран согласия
- **AND** после согласия сервер сохраняет access и refresh token, привязанные к пользователю

##### Scenario: Несовпадение пользователя
- **WHEN** логин в Confluence после OAuth не совпадает с пользователем Keycloak, начавшим подключение
- **THEN** токен не сохраняется, подключение отклоняется с ошибкой

#### Requirement: Жизненный цикл токенов

Токены SHALL храниться зашифрованными (ключ шифрования вне БД) и обновляться через refresh token.

##### Scenario: Истёк access token
- **WHEN** access token истёк, refresh token действует
- **THEN** сервер обновляет токен прозрачно для пользователя

##### Scenario: Отозван доступ в Confluence/Jira
- **WHEN** refresh token отклонён
- **THEN** сервер удаляет токены и снова возвращает ссылку «Разрешить доступ»

##### Scenario: Отключение пользователем
- **WHEN** пользователь нажимает «Отключить Confluence» на странице «Мои доступы»
- **THEN** токены удаляются у нас, сервер больше не обращается к Confluence от его имени
- **AND** пользователю подсказывают, где отозвать само разрешение в профиле Confluence (см. Design → Ограничения: у DC нет API отзыва)

##### Scenario: Сотрудник заблокирован
- **WHEN** учётка заблокирована в AD/Keycloak
- **THEN** вход в Open WebUI и на страницу «Мои доступы» перестаёт работать
- **AND** когда Confluence/Jira отклоняют обновление токена, сервер удаляет грант, и вызовы с его ключами перестают получать данные

#### Requirement: Отзыв доступа администратором

Администратор SHALL иметь возможность сразу и полностью отозвать доступ человека, не дожидаясь истечения токенов.

##### Scenario: Офбординг
- **WHEN** администратор выполняет `atlassian-mcp user offboard -username X`
- **THEN** все действующие ключи X отзываются, следующий вызов с ними получает 401
- **AND** гранты X в Confluence и Jira удаляются, его вызовы больше не доходят до Atlassian
- **AND** выводится список автономных агентов, владельцем которых был X, для переназначения
- **AND** действие с исполнителем пишется в аудит; повторный запуск ничего не меняет

### Capability: confluence-tools

#### Requirement: Поиск

Инструмент `confluence_search` SHALL искать по фразе (все слова, а не любое), с опциональными фильтрами по пространству, автору, дате изменения и заголовку.

##### Scenario: Поиск по ФИО
- **WHEN** запрос «Иван Иванов»
- **THEN** CQL ищет страницы, содержащие оба слова
- **AND** результаты ранжируются по релевантности

##### Scenario: Поиск по автору
- **WHEN** задан фильтр `author=i.ivanov`
- **THEN** CQL содержит `creator = "i.ivanov"`

##### Scenario: Попытка инъекции
- **WHEN** запрос содержит кавычки, `OR`, `AND`, скобки или иные конструкции CQL
- **THEN** они экранируются и ищутся как текст, логика запроса не меняется

##### Scenario: Нет доступа к пространству
- **WHEN** пользователь ищет в пространстве, к которому у него нет прав в Confluence
- **THEN** результаты из него не возвращаются (ограничивает сам Confluence)

#### Requirement: Получение страницы

Инструмент `confluence_get_page` SHALL возвращать текст страницы по id или ссылке с заголовком, пространством, автором, датой изменения и ссылкой.

#### Requirement: Источники

Каждый результат SHALL содержать ссылку на страницу, чтобы Open WebUI показывал источники.

---

### Capability: jira-tools

#### Requirement: Чтение

Инструменты `jira_search` (JQL с экранированием пользовательского текста), `jira_get_issue` (задача, статус, исполнитель, описание, комментарии) SHALL работать под токеном субъекта.

##### Scenario: Задача в закрытом проекте
- **WHEN** пользователь запрашивает задачу проекта, к которому нет доступа
- **THEN** возвращается «не найдено / нет доступа», содержимое не раскрывается

#### Requirement: Запись (фаза 2, после отдельного согласования)

Создание задач и комментариев SHALL быть выключено по умолчанию. После включения каждое изменяющее действие SHALL требовать явного подтверждения пользователем.

##### Scenario: Запрос на создание задачи при выключенной записи
- **WHEN** модель вызывает `jira_create_issue`, а запись выключена
- **THEN** сервер отказывает с понятным сообщением

В фазе 1 инструментов записи нет вовсе: в списке инструментов только четыре читающих, вызов несуществующего инструмента отклоняется MCP-сервером.

---

### Capability: audit

#### Requirement: Журнал вызовов

Сервер SHALL логировать каждый вызов: время, субъект (пользователь / ключ / агент), канал (Open WebUI / ключ / client credentials), инструмент, параметры запроса, число результатов, статус. Содержимое страниц и задач SHALL NOT логироваться.

##### Scenario: Расследование
- **WHEN** ИБ запрашивает, что искал пользователь X за период
- **THEN** журнал даёт список вызовов с параметрами, без содержимого документов

#### Requirement: Срок хранения аудита

Записи аудита старше `AUDIT_RETENTION` (по умолчанию 1 год) SHALL удаляться автоматически раз в сутки. Значение `0` отключает удаление.

##### Scenario: Истёк срок хранения
- **WHEN** запись старше срока хранения
- **THEN** она удаляется при ближайшей ежесуточной очистке, более свежие записи не затрагиваются

#### Requirement: Метрики

Сервер SHALL отдавать метрики Prometheus: число вызовов по инструментам, ошибки, задержки, число подключённых пользователей.

---

### Capability: non-functional

#### Requirement: Не блокировать клиентов

Все обращения к Confluence/Jira SHALL быть асинхронными. Медленный запрос одного пользователя не влияет на остальных.

#### Requirement: Ограничения

- Таймаут обращения к Atlassian — 20 с.
- Лимит результатов поиска — до 20, текст страницы обрезается до настраиваемого лимита.
- Rate limit на субъекта — настраиваемый.

#### Requirement: Транспорт

Сервер SHALL работать по MCP Streamable HTTP и подключаться к Open WebUI, OpenCode и другим MCP-клиентам без доработки.

## 3. Design

### Схема

```
                         ┌───────────────── Keycloak ─────────────────────────────────────────┐
                         │  SSO пользователей · client credentials агентов                    │
                         └──────────────▲──────────────────────────────▲─────────────────────┘
                                        │                              │
 Пользователь ─► Open WebUI ──(SSO-токен)──►┐                          │
 OpenCode / скрипт ─────(персональный ключ)─►├─► atlassian-mcp ──(OAuth-токен субъекта)──► Confluence DC 9.2
 Прод-агент ─────────(client credentials)───►┘     │  │                                     Jira DC
                                                   │  └─► аудит (Postgres) · метрики (Prometheus)
                                                   └─► хранилище токенов (Postgres, шифрование)
```

### Компоненты

| Компонент | Решение |
|---|---|
| Язык / фреймворк | Go 1.25, официальный MCP Go SDK (Streamable HTTP, stateless), pgx, go-oidc |
| Хранилище | PostgreSQL: пользователи, зашифрованные токены, хеши ключей, реестр агентов, аудит |
| Шифрование токенов | AES-GCM, ключ из секрета окружения (не в БД) |
| Веб-страница «Мои доступы» | SSO через Keycloak (OIDC): подключить/отключить Confluence/Jira, выпустить/отозвать ключи |
| Проверка Keycloak-токенов | JWKS доверенного realm, разрешённые `azp`: `open-webui` + клиенты из реестра агентов |
| Развёртывание | Пилот: Docker Compose на одном хосте рядом с Open WebUI. Прод: см. Open Questions, п. 5 |
| Адрес | Отдельное HTTPS-имя (TLS, доступно из браузеров: OAuth redirect) |

### Почему так

- **OAuth через Confluence, а не проброс Keycloak-токена.** Проверено 29.10: Confluence DC отвечает 401 на Keycloak-токены в REST API — SSO у него только для браузера.
- **Идентификация по Keycloak-токену, а не через MCP-OAuth Open WebUI.** Не зависим от зрелости MCP-OAuth в Open WebUI 0.12 и от поддержки Dynamic Client Registration (в Confluence её нет). Пользователь не может выдать себя за другого: токен подписан Keycloak.
- **Свой сервер, а не готовый mcp-atlassian.** Готовые реализации заточены под Atlassian Cloud; для DC, нашей схемы идентификации и аудита их пришлось бы переписывать.
- **Модель на self-hosted LLM.** Содержимое Confluence/Jira не уходит во внешние облака.

### Ограничения и решения реализации

- **403 для незарегистрированных клиентов.** MCP SDK возвращает 403 только при нехватке scope. Каждому допущенному субъекту выдаётся внутренний scope `atlassian-mcp:access`, обработчик MCP его требует; валидный токен незарегистрированного клиента получает 403.
- **Отзыв разрешения в Confluence/Jira.** У OAuth 2.0-провайдера Data Center нет API отзыва токенов (проверить на 9.2.8). «Отключить» удаляет токены у нас; само разрешение пользователь отзывает в профиле продукта. Выданный продуктом access-токен формально живёт до своего срока, но у сервера его больше нет.
- **Блокировка сотрудника.** Сервер не опрашивает AD/Keycloak о статусе учёток. Автоматически доступ пропадает, когда Atlassian отклоняет обновление токена; немедленно — командой `user offboard`. Её нужно встроить в процесс увольнения (предложение для ИБ). Ключи ограничены сроком: по умолчанию 90 дней, максимум 180.
- **Сессия страницы «Мои доступы»** живёт до `SESSION_TTL` (8 ч). После офбординга заблокированный сотрудник в открытой сессии может выпустить ключ, но данных через него не получит: подключить Confluence/Jira заново он не сможет.

### Замечания для ИБ

- Срок жизни access-токена Keycloak должен быть коротким (минуты, не сутки): этим токеном Open WebUI ходит в сервис.
- Если realm Open WebUI используется и для других приложений, стоит оценить разделение.
- Модель задач Open WebUI (заголовки, теги) получает фрагменты чатов. Если она во внешнем облаке, данные Confluence уходят туда. Варианты: модель задач на self-hosted LLM или отключение генерации для этой модели.

### Риски

| Риск | Митигирование |
|---|---|
| Компрометация хранилища токенов | Шифрование, ключ вне БД, доступ к БД только у сервиса, короткий срок access-токенов |
| Утечка персонального ключа агента | Срок жизни, отзыв, хранение хеша, аудит по ключу |
| Широкие права служебной учётки агента | Учётка на каждого агента, минимальные пространства/проекты, только чтение по умолчанию, владелец агента в реестре |
| Модель неверно использует инструмент | Ограниченный набор инструментов, запись выключена, подтверждение изменений |
| Недоступность Confluence/Jira | Таймауты, понятная ошибка пользователю, метрики и алерт |
