# access-scope Specification

## Purpose

Ограничение сервиса согласованными пространствами Confluence и проектами Jira (требование ИБ для пилота). Ограничение применяется на сервере независимо от прав пользователя в самом продукте: даже если у пользователя есть доступ к объекту, вне списка сервис его не вернёт. Охватывает конфигурацию списков, тулы `confluence_search`, `confluence_get_page`, `jira_search`, `jira_get_issue` и их описания для модели. Аудит отказов описан в capability аудита. Исходники: `internal/scope/scope.go`, `internal/tools/tools.go`, `internal/config/config.go` (`validateAllowed`).

## Requirements

### Requirement: Обязательный список при включённом продукте

Сервис MUST отказываться стартовать, если продукт (Confluence или Jira) включён, а список разрешённых ключей (`CONFLUENCE_ALLOWED_SPACES` / `JIRA_ALLOWED_PROJECTS`) не задан. Значение `*` SHALL снимать ограничение; `*` вместе с другими ключами и ключи неверного формата MUST отклоняться.

#### Scenario: Список не задан

- **GIVEN** Confluence включён, `CONFLUENCE_ALLOWED_SPACES` не задан
- **WHEN** сервис загружает конфигурацию
- **THEN** загрузка завершается ошибкой «CONFLUENCE_ALLOWED_SPACES is required»

#### Scenario: Звёздочка вместе с ключами

- **GIVEN** `CONFLUENCE_ALLOWED_SPACES=*,HR`
- **WHEN** сервис загружает конфигурацию
- **THEN** загрузка завершается ошибкой `invalid key "*"`

#### Scenario: Ключ с попыткой инъекции

- **GIVEN** `CONFLUENCE_ALLOWED_SPACES` содержит `TECH") OR space`
- **WHEN** сервис загружает конфигурацию
- **THEN** загрузка завершается ошибкой «invalid key»

### Requirement: Незаданное ограничение запрещает всё

Ограничение без ключей и без `*` SHALL запрещать доступ к любому объекту (fail-closed).

#### Scenario: Пустое ограничение

- **GIVEN** ограничение пространств и проектов пустое
- **WHEN** пользователь ищет в Confluence, читает страницу или задачу Jira
- **THEN** сервис не возвращает ни одного результата, страницы или задачи

### Requirement: Сравнение ключей

Ключи SHALL сравниваться без учёта регистра и окружающих пробелов; дубликаты в списке игнорируются.

#### Scenario: Ключ в другом регистре

- **GIVEN** разрешены `TECHOPS` и `~i.ivanov`
- **WHEN** проверяются ключи `techops` и ` ~I.IVANOV `
- **THEN** оба ключа разрешены

### Requirement: Поиск в Confluence в пределах списка

Поиск SHALL по умолчанию выполняться только по разрешённым пространствам. Запрос пространства вне списка MUST отклоняться до обращения к Confluence с перечнем доступных пространств. Результаты из пространств вне списка MUST отбрасываться и не попадать в ответ и аудит.

#### Scenario: Поиск без указания пространств

- **GIVEN** разрешено только `TECHOPS`
- **WHEN** пользователь ищет без указания пространств
- **THEN** запрос в Confluence ограничен пространством `TECHOPS`

#### Scenario: Запрошено пространство вне списка

- **GIVEN** разрешено только `TECHOPS`
- **WHEN** пользователь ищет в пространстве `HR`
- **THEN** обращения к Confluence нет, ошибка перечисляет `TECHOPS`, статус аудита `invalid`

#### Scenario: Confluence вернул результат вне списка

- **GIVEN** разрешено только `TECHOPS`, Confluence вернул страницы из `TECHOPS` и `HR`
- **WHEN** сервис формирует ответ
- **THEN** в ответе и в объектах аудита только страница из `TECHOPS`

### Requirement: Чтение страницы вне списка

Страница из пространства вне списка MUST NOT возвращаться. Ответ SHALL совпадать с ответом для несуществующей страницы и не раскрывать ключ пространства; аудит фиксирует статус `out_of_scope` и ID страницы.

#### Scenario: Страница в чужом пространстве

- **GIVEN** разрешено только `TECHOPS`, страница 2 лежит в `HR`
- **WHEN** пользователь читает страницу 2
- **THEN** ответ «не найдено … или нет прав доступа» без упоминания `HR`, в аудите статус `out_of_scope`, объект `2`, 0 результатов

### Requirement: Поиск в Jira в пределах списка

Поиск SHALL по умолчанию выполняться только по разрешённым проектам; проект вне списка MUST отклоняться до обращения к Jira. Произвольный JQL MUST быть недоступен, пока список проектов ограничен, и SHALL быть доступен при `*`. Задачи из проектов вне списка MUST отбрасываться из ответа и аудита.

#### Scenario: Произвольный JQL при ограниченном списке

- **GIVEN** разрешён только `OD`
- **WHEN** пользователь передаёт JQL `project = HR`
- **THEN** запрос отклонён с сообщением «raw jql is not available»

#### Scenario: Произвольный JQL без ограничения

- **GIVEN** разрешены все проекты (`*`)
- **WHEN** пользователь передаёт JQL `project = HR`
- **THEN** запрос выполняется

#### Scenario: Проект вне списка

- **GIVEN** разрешён только `OD`
- **WHEN** пользователь ищет в проекте `HR`
- **THEN** запрос отклонён до обращения к Jira

### Requirement: Чтение задачи вне списка

Задача из проекта вне списка MUST NOT возвращаться; проверка по ключу SHALL выполняться до обращения к Jira. Задача, перенесённая в проект вне списка, MUST NOT возвращаться; аудит фиксирует исходный и новый ключ.

#### Scenario: Ключ из чужого проекта

- **GIVEN** разрешён только `OD`
- **WHEN** пользователь читает `HR-5`
- **THEN** обращения к Jira нет, ответ «не найдено … или нет прав доступа»

#### Scenario: Задача перенесена из списка наружу

- **GIVEN** разрешён только `OD`, задача `OD-9` перенесена и теперь `HR-9`
- **WHEN** пользователь читает `OD-9`
- **THEN** задача не возвращается, в аудите статус `out_of_scope`, объекты `OD-9, HR-9`

### Requirement: Описания тулов перечисляют доступные ключи

При ограниченном списке описания тулов SHALL перечислять доступные пространства и проекты, а описание поиска Jira — сообщать, что произвольный JQL недоступен. При `*` перечень не выводится.

#### Scenario: Ограниченный список проектов

- **GIVEN** разрешён только `OD`
- **WHEN** модель получает список тулов
- **THEN** описание `jira_search` содержит `OD` и «Raw JQL is not available»
